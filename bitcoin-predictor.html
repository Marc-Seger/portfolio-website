Bitcoin Price Predictor

XGBoost, Python, Streamlit, GitHub Actions

The idea

The first version of this was a Le Wagon bootcamp project: a Streamlit dashboard and a first pass at price prediction, built in notebooks over a few weeks. It worked well enough to learn from, but it wasn't something I'd want a hiring manager to actually open.

I rebuilt it from scratch as v2: real Python modules instead of notebooks, a daily pipeline that fetches data and retrains itself via GitHub Actions, and an evaluation method honest enough that I'd trust the numbers myself.

How it works

Every day at 22:00 UTC, right after the NYSE close, a GitHub Actions workflow pulls fresh data across BTC, cross-asset prices, macro indicators, on-chain metrics, and sentiment, validates it, retrains an XGBoost model on the full history, and generates a new 7-day return prediction, no manual step anywhere in that chain.

Evaluation uses non-overlapping 7-day walk-forward windows, so each prediction is scored independently rather than flattered by a single bull-market backtest.

A five-page Streamlit app sits on top: market dashboard, live forecast, strategy backtesting lab, model performance tracking, and documentation, plus a weekly job that flags drift automatically. An adversarial audit of the pipeline caught 13 real bugs, including two multi-day silent data gaps, both fixed with checks against recurrence.

Results

Across 2,467 non-overlapping walk-forward predictions, the tuned model calls the 7-day direction correctly 76.7% of the time, against a 52.3% naive baseline. When the model is most confident, that accuracy climbs to 90.6%. Tree-based models (XGBoost) outperformed LSTM/GRU alternatives tested on this dataset size (~50% accuracy).

These numbers are recalculated from the walk-forward results file every time the app loads, not hard-coded.
