Bitcoin Price Predictor

XGBoost, Python, Streamlit, GitHub Actions

The idea

The first version of this was a Le Wagon bootcamp project: a Streamlit dashboard and a first pass at price prediction, built in notebooks over a few weeks. It worked well enough to learn from, but it wasn't something I'd want a hiring manager to actually open.

I rebuilt it from scratch as v2: real Python modules instead of notebooks, a daily pipeline that fetches data and retrains itself via GitHub Actions, and an evaluation method honest enough that I'd trust the numbers myself.

Built with, not by

I built this working with Claude Code as my engineering partner: I made the calls, it wrote the code.

Early on, the backtest accuracy looked good, mostly because BTC has spent most of this cycle in a bull market, so almost any model looks smart when the trend is up. I decided on a walk-forward evaluation instead: non-overlapping 7-day windows, so each prediction is scored independently and errors can't hide behind a lucky trend. The honest number came back lower, 55.2% direction accuracy against a 52.3% naive baseline, but it was the real one, and it's the number that's on this site.

I also made the call to predict 7-day return instead of raw price. Tree-based models like XGBoost can't extrapolate past the range of values they were trained on, so a model trained on BTC between $20k and $100k literally cannot output a price above that range, no matter how the market moves. Predicting the percentage change instead sidesteps that ceiling entirely.

How it works

Every day at 22:00 UTC, right after the NYSE close, a GitHub Actions workflow pulls fresh data: BTC and cross-asset prices, macro indicators from FRED, on-chain metrics, sentiment, and more. It validates the data, retrains the XGBoost model on the full history, generates a new 7-day prediction, and commits the result. No manual step anywhere in that chain.

The Streamlit app on top of it has five pages: a market dashboard, the live forecast, a strategy backtesting lab, model performance tracking, and documentation that's honest about what the model can and can't do. A separate weekly job checks the model's live accuracy and opens a GitHub issue if it starts drifting.

Results

Across 2,467 non-overlapping walk-forward predictions, the tuned model calls the 7-day direction correctly 76.7% of the time, against a 52.3% naive baseline. When the model is most confident, that accuracy climbs to 90.6%.

Those numbers come from Optuna hyperparameter tuning on top of a much rougher first pass, 55.2% direction accuracy pre-tuning, and they're recalculated from the walk-forward results file every time the app loads, not hard-coded.
