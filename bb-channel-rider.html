Systematic BTC Strategies

Python, Backtesting, MEXC Futures, Flask

The idea

This started as a much bigger, messier project: a bot that followed trade signals from a Telegram channel. That version never goes public, not the code, not even in its git history, since it's tied to a real trading account. What's here is a clean extraction of the part that actually stands on its own: five rules-based BTC strategies sharing one indicator library and one backtest engine, no external signals, no discretionary input, just OHLCV candles in and trades out.

Only one of the five, BB Channel Rider, has been through full validation and runs live in paper mode. The other four exist to build and test ideas, not to be trusted as-is, and I'm upfront about that distinction rather than presenting all five as equally proven.

The bot

BB Channel Rider is a mean-reversion strategy on BTC/USDT perpetual futures, 15-minute candles, 10x leverage, 25% of capital per trade. It enters when price touches a Bollinger Band (20-period, 3.0 standard deviations) in the direction confirmed by an EMA-150 trend filter, then manages the position with a dual stop-loss (a stop-limit plus a market backstop in case price gaps through it), a stop that snaps to breakeven and then trails in the profitable direction as price moves, and a take-profit at the opposite band. When take-profit hits and price is still sitting at the band, the bot immediately flips into the opposite position instead of sitting idle. The full spec was frozen on 2026-05-10 and hasn't changed since.

It runs as a systemd service on an Oracle Cloud VPS with automatic restart, alongside a Flask dashboard for backtesting any of the five strategies and watching live status. The API key is read-only and locked to the server's IP, and paper mode never sends an order to the exchange, it only reads live prices.

Live record

Running since August 2026 on a $1,000 paper balance. As of the last check it has closed 27 trades, -$18.94 net, currently flat. Far too few trades to conclude anything on its own, which is exactly why it stays running, but it's a useful cross-check against the out-of-sample backtest below: both land close to breakeven over roughly the same period. This is the number I'd want judged in a year, not the backtest. Full detail is on the dashboard, linked below.

What the backtest says

I originally published +$730.45 on a $1,000 start, a 73% return. It was wrong, twice.

The first correction, in August, fixed an audit script that had drifted from the deployed bot on five counts, every one flattering. That produced 311 trades, 60.5% win rate, +$730.45, 20.1% maximum drawdown, and I published it as the honest number. It stayed wrong.

The second mistake was in the simulation itself, not the audit script around it. It tested each candle's wick against a Bollinger Band computed from that same candle's own close, a level not knowable at the moment it would have to act on it. The live bot only ever uses the last closed candle's band, because that's the only level it can actually rest an order on. A separate bug froze the stop-loss snap threshold at trade entry instead of recalculating it every candle, contradicting the strategy's own frozen spec and the live bot's real behavior. Both bugs point the same way: toward a friendlier fill than the live bot could ever get.

Corrected, the same year of data gives 437 trades, 53.8% win rate, -$683.90 on the same $1,000 start, a 68% loss, 72.8% maximum drawdown.

That full-period number isn't the one to trust either, and not because it's bad news this time, because it includes the exact window the parameters were selected from, which flatters any evaluation run over it. The honest test is the period after the 2026-05-10 spec freeze, which the parameter search never saw: 116 trades, 57.8% win rate, +$5.62, 18.1% maximum drawdown. Essentially breakeven.

There's a real gross signal underneath, just not enough of one. The same out-of-sample window with fees switched off returns +$396 instead of +$6. Even the full period is barely positive gross, +$70 against the -$684 net result above. At 10x leverage a round trip costs roughly 1.2% of margin, enough to erase a thin edge entirely.

The 16,200-combination grid search that selected these parameters (67.5% of combinations profitable, this configuration ranking 14th) was run under the old, over-optimistic simulation and hasn't been re-checked under the corrected one, so I'm not citing it as evidence here until it has been.

Known limitations

Paper mode uses real prices and models fees, but assumes zero slippage and instant fills, so live trading would run somewhat below these numbers. The backtest can't distinguish a stop-limit fill from the market backstop, so stop-loss exits are costed at the cheaper maker rate. The other four strategies share the same engine but haven't been through this validation.

These figures replace two earlier sets. The original, 290 trades, 63.8%, +$10,348, came from an audit script that had drifted from the deployed strategy on five counts, each flattering, and was measuring a configuration that never ran. The one that replaced it, 311 trades, 60.5%, +$730.45, fixed that but carried its own, deeper bug in the simulation logic itself. Both are documented in full on the repo, including the fix that makes the audit import the live strategy module directly so it can't drift from the deployed bot again.
